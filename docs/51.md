# Work #51: Allow temporary test executables inside Codex container

Implementation PR: https://github.com/charsyam/swfactory/pull/51
Issue: [#50](https://github.com/charsyam/swfactory/issues/50)
Affected approved issues: [#32](https://github.com/charsyam/swfactory/issues/32), [#33](https://github.com/charsyam/swfactory/issues/33)

## What and why

The controller's Docker command mounted a private `/var/tmp` tmpfs without executable permission. Python tests create temporary `gh` and `ssh` fixture programs there. Their `os.access(X_OK)` checks failed, so the verifier stopped the first approved sub-task even though its new tests passed. A direct Docker probe reproduced the failure; adding `exec` made both the executable check and invocation succeed.

## Sequence and implementation policy

1. Add `exec` to the existing `/var/tmp` tmpfs options. Keep its user ID, group ID, private mode, and Docker isolation settings.
2. Add an opt-in integration test using the controller's actual Docker command. Write a small executable in `/var/tmp`, assert it is executable, and run it in a read-only-worktree container.
3. Document why the temporary mount is executable. The workspace mount and credential boundary remain controlled by Docker; this option grants execution only inside the container's private temporary file system.
4. Re-run the blocked approved issues after deployment.

## Alternatives

Moving temporary fixtures to the worktree would bypass the failing temporary mount but change the tests' intended environment. Skipping the existing environment tests would weaken verification. Making the private tmpfs executable supports the standard Python fixture behavior directly.

## Tests and observed results

- Basic: `python3 -m py_compile swfactory.py` and `git diff --check` passed.
- Functional: the existing unit suite passed.
- Integration: `SWFACTORY_DOCKER_INTEGRATION=1 python3 -m unittest discover -s tests -q` passed 60 tests, including the new real Docker executable probe and the existing live Codex boundary tests.
