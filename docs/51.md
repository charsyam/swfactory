# Work #51: Allow temporary test executables inside Codex container

Implementation PR: https://github.com/charsyam/swfactory/pull/51
Issue: [#50](https://github.com/charsyam/swfactory/issues/50)
Affected approved issues: [#32](https://github.com/charsyam/swfactory/issues/32), [#33](https://github.com/charsyam/swfactory/issues/33)

## What and why

The controller's Docker command mounted a private `/var/tmp` tmpfs without executable permission. Python tests create temporary `gh` and `ssh` fixture programs there. Their `os.access(X_OK)` checks failed, so the verifier stopped the first approved sub-task even though its new tests passed. A direct Docker probe reproduced the failure; adding `exec` made both the executable check and invocation succeed. The image also omitted `gh` and `ssh`, which made the existing offline doctor tests fail before their fixtures ran.

## Sequence and implementation policy

1. Add `exec` to the existing `/var/tmp` tmpfs options. Keep its user ID, group ID, private mode, and Docker isolation settings.
2. Install the `gh` and OpenSSH client executables in the image so the normal repository test suite can run. The controller's GitHub token and SSH key remain absent from the container.
3. Add opt-in integration tests using the actual Docker image and command. Run an executable from `/var/tmp` and assert both required executables are available.
4. Document why the temporary mount is executable. The workspace mount and credential boundary remain controlled by Docker; this option grants execution only inside the container's private temporary file system.
5. Re-run the blocked approved issues after deployment.

## Alternatives

Moving temporary fixtures to the worktree would bypass the failing temporary mount but change the tests' intended environment. Skipping the existing environment tests would weaken verification. Adding temporary stubs for `gh` and `ssh` would conceal the image's missing dependencies. Making the private tmpfs executable and supplying the test suite's declared tools supports the standard test behavior directly.

## Tests and observed results

- Basic: `python3 -m py_compile swfactory.py` and `git diff --check` passed.
- Functional: the existing unit suite passed.
- Integration: `SWFACTORY_DOCKER_INTEGRATION=1 python3 -m unittest discover -s tests -q` must pass with the rebuilt image, including real Docker executable and tool-availability probes and the existing live Codex boundary tests.
