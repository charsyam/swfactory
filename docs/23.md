# Work #23: Close tracked issues after task PRs merge

Implementation PR: https://github.com/charsyam/swfactory/pull/23
Related issues: [#22](https://github.com/charsyam/swfactory/issues/22), [#1](https://github.com/charsyam/swfactory/issues/1)

## What

Close each generated sub-issue only after its own implementation PR is merged. Close the parent only after every generated task PR is merged. Work #23 also hardens the retry path that was needed to complete the doctor task PRs for issue #1.

## Why

The old controller closed sub-issues as soon as it opened PRs. That advertised completion before any code was merged. Stacked PRs target earlier task branches, so GitHub closing keywords do not consistently close the issues when the stack is merged. Retry planning can reword task titles and produce GitHub PR checks that the isolated Codex worktree cannot access.

## Sequence and implementation policy

1. Record a task's completed implementation with its PR URL and `done` label, leaving its issue open. Skip repeated records when `done` already exists.
2. At the start of every trigger, list open `done` issues. Treat only a parent with a swfactory sub-task link section and an owner-applied `accept` event as eligible for reconciliation.
3. Read the ordered child issue numbers from that section. For each index, query all PRs with the deterministic `swfactory/issue-{parent}-task-{index}` head. Require exactly one PR with the expected sub-issue title prefix and `MERGED` state.
4. If the matching PR is merged, close the corresponding open sub-issue only when it carries `swfactory:subtask`. Leave unmatched or unmerged issues open. After every task PR is merged, close the parent. A second trigger sees the closed parent and does not duplicate the closure.
5. Reuse an open task PR on retry based on its sub-issue number, head branch, and base branch; fresh prose in a plan is not a stable identity. Accept qualified test method names in verification. Keep PR metadata checks with the controller and give Codex only local integration tests.

## Alternative ways

GitHub closing keywords alone are simpler for a single PR targeting the default branch. They do not cover stacked PRs whose intermediate bases are task branches. Webhooks could close issues immediately after each merge, but this tool already runs periodically and a poll-based reconciler avoids a new service.
