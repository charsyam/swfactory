# Work #5: Issue questions and periodic execution

GitHub issue: [#5](https://github.com/charsyam/swfactory/issues/5) · Parent: [#3](https://github.com/charsyam/swfactory/issues/3) · Implementation PR: [#2](https://github.com/charsyam/swfactory/pull/2)

## What and why

An approved issue can still lack essential requirements. Implementing guessed behavior would produce a PR the owner did not intend. The planner can now return explicit questions, pause the issue, and resume after the configured owner answers in a GitHub issue comment. The existing one-shot command can be scheduled hourly or every two hours through cron.

## Sequence and design

1. Add `questions` to the structured planner response. When it is nonempty, post numbered questions in the source issue with an `@OWNER_GITHUB_HANDLE` mention and a hidden marker identifying the question comment.
2. Replace `swfactory:running` with `swfactory:waiting`. The queue excludes waiting issues, so no implementation begins while the requirement is unresolved.
3. At each one-shot run or watch poll, list waiting issues and their comments. Find the latest swfactory question marker. Resume only if a later comment is authored by the configured owner. Comments by other users do not release the issue.
4. Remove the waiting label and run planning again with recent issue comments as context. If the answer is still incomplete, the planner may ask another focused question.
5. The `OWNER_GITHUB_HANDLE` setting defaults to the repository owner login, and can be explicitly set for an organization repository or a different maintainer.
6. Document cron entries for one-hour and two-hour intervals. Cron invokes the existing one-shot command; a per-repository file lock prevents overlap. Scheduling is not installed automatically because the user has not selected the interval or asked to change their system crontab.

## Tests and limitations

Unit tests check that waiting issues stay out of the normal queue, unrelated comments do not resume an issue, and an owner comment after the latest question does. A live one-shot run on issue #1 recognized the owner's answer and removed `swfactory:waiting`. Cron execution has not been run.

The current completion gate still uses Codex's structured test report. Direct command exit-code verification and GitHub CI checks remain separate future work.
