### 2. 세부 작업

#### 1. 1. Separate configuration reading and validation from normal-run setup.
- 무엇: 1. Separate configuration reading and validation from normal-run setup.
- 이유: Doctor needs every configuration error, while normal execution must retain its existing fail-fast behavior and `WORK_DIR` creation.
- 방법 및 구현 정책: In `swfactory.py`, extract the existing `env` parser and value selection into reusable functions. Preserve the current `--repository` and `--project-path` override precedence, SSH URL format, optional `WORK_DIR=/tmp`, path expansion, and case-insensitive repository comparison. Return structured findings for missing or malformed settings instead of raising on the first finding. Keep `config()` as a compatibility wrapper that raises on failure and creates `WORK_DIR` only for normal execution. Do not print raw `env` lines, secret values, key contents, or subprocess stderr. Do not reject a `WORK_DIR` that is an ancestor of the checkout: the current `/tmp` default commonly has that relationship.
- 테스트: Basic: missing `env` and each missing required value produce named findings without a traceback. Functional: invalid SSH URL, missing key, missing project, and both override options are checked independently; a valid configuration yields the same five values as `config()`. Integration: rerun the existing `test_repository_override_selects_another_project` and verify normal `config()` still creates `WORK_DIR` while the extracted diagnostic path does not.
