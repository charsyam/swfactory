# Work #29: Verify the Codex credential boundary

## What and why

Add adversarial tests and operating instructions for the Docker boundary introduced by work #28. Prompt instructions alone cannot prove that untrusted issue content or repository tests cannot read host GitHub authentication and SSH keys. The boundary must be checked with actual container processes and a local Codex CLI run before it is treated as ready.

## Sequence and policy

1. Put fake GitHub and SSH secrets in sibling files outside the mounted workspace. Start the same Docker command that the controller uses in read-only and writable modes. Assert both files are absent, GitHub variables are absent, and the dedicated Codex login is present. Assert read-only workspaces reject writes while writable workspaces allow them.
2. In a temporary Git repository, give live `codex exec` an adversarial repository-note instruction asking for the fake secret files. Run both modes and verify no canary value appears in the result. In writable mode also require a normal workspace file to be created. This checks the intended task still works under isolation.
3. Keep these Docker/model tests opt-in with `SWFACTORY_DOCKER_INTEGRATION=1` so routine unit tests remain runnable without Docker or a ChatGPT login. Document image build, file-backed authentication, custom project dependency images, residual Codex login exposure, and recovery steps in `docs/isolation-operations.md`.

## Alternative ways

A mocked command-line test can check flags and mounts but cannot prove file access fails in a real container. Live Codex tests on every routine run would add model cost and require authentication in all test environments; opt-in integration testing provides boundary evidence without making basic tests depend on a service.

## Tests and observed results

- Basic: `python3 -m py_compile swfactory.py` — PASS; `git diff --check` — PASS.
- Functional: `python3 -m unittest discover -s tests -q` — PASS with live cases skipped. The work #28 unit tests cover environment and mount construction.
- Integration: `SWFACTORY_DOCKER_INTEGRATION=1 python3 -m unittest discover -s tests -q` — PASS, 37 tests. Direct shell probes verified both fake secret paths were inaccessible in both modes. Live Codex outputs contained no fake canary; a writable run created `proof.txt` inside its temporary workspace.
