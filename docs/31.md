# Work #31: Fix scan inspection inside Docker

Implementation PR: https://github.com/charsyam/swfactory/pull/31
Issue: [#30](https://github.com/charsyam/swfactory/issues/30)

## What and why

The first real repository scan could not read its worktree because Codex tried to initialize its Linux read-only sandbox inside Docker. Codex then returned an empty finding list, and the controller recorded the commit as successfully scanned. This silently suppressed future scans of that commit.

## Sequence and implementation policy

1. Keep Docker's read-only container root, read-only scan worktree bind mount, read-only Git metadata, minimal environment, and absence of the Docker socket. Run the Codex CLI with inner `danger-full-access` for both read-only and writable calls. The inner Linux sandbox cannot initialize reliably in the container; Docker remains the file boundary.
2. Require every scan response to contain `inspection.path` and `inspection.sha256`. Instruct Codex to read a source file with a shell tool and calculate its SHA-256, including when no issues are found.
3. Resolve the returned repository-relative path within the detached snapshot. Reject absolute paths, parent traversal, paths outside the snapshot, missing files, malformed digests, and digests that do not match the file bytes. Perform validation before querying or writing GitHub issues.
4. Record the scan commit only after the inspection and proposal processing succeed. Increment the scan policy version from 1 to 2, forcing a retry of commits previously recorded as successful by the broken policy.
5. Document the Docker boundary and inspection proof in the README and isolation operating notes.

## Alternatives

Using Codex's nested Linux read-only sandbox would give another boundary, but it failed to initialize in the actual Docker run and blocked all file reads. Accepting a structured empty issue list without proof would preserve the false-success failure mode. The digest proves the CLI could read at least one snapshot source file while Docker retains the access restriction.

## Tests and observed results

- Basic: `python3 -m py_compile swfactory.py` and `git diff --check` pass.
- Functional: 59 tests pass. A new test rejects an empty result with missing, wrong, or outside-snapshot inspection data and accepts a valid source digest.
- Integration: `SWFACTORY_DOCKER_INTEGRATION=1 python3 -m unittest discover -s tests -q` passes all 59 tests, including live Docker and Codex boundary checks. A real scan on the isolated branch read `swfactory.py`, computed its SHA-256, and returned one code-supported proposal; GitHub writes were mocked during this validation.
