# Work #11: Test cases and execution evidence

GitHub issue: [#11](https://github.com/charsyam/swfactory/issues/11) · Parent: [#3](https://github.com/charsyam/swfactory/issues/3) · Implementation PR: [#2](https://github.com/charsyam/swfactory/pull/2)

## What and why

Each implemented sub-task needs an automated test case for its behavior. The PR and parent issue also need concrete execution results for basic, functional, and integration tests so the owner can review the outcome before merging.

## Detailed sequence and policy

1. Ask the planner to specify test cases for every small task, plus basic, functional, and integration checks for the whole issue.
2. In each implementation pass, direct the local Codex CLI to add or extend automated test cases and run the task's tests.
3. In the verification pass, require a structured list of added cases, with task number, file path, case name, and behavior. Require a structured result for each test category with the actual command, observed output or result summary, and pass status.
4. Reject a verification that omits any sub-task's new test case. Confirm each reported case's file changed in the worktree, exists, and contains the reported case name.
5. Reject a verification that omits a basic, functional, or integration result, reports a failed run, or lacks a command or observed output. Keep the existing rule that the verifier must actually run the tests before setting `passed=true`.
6. Include the test cases and execution results in the PR description and the parent issue completion comment. Continue to leave the PR merge to the owner.

## Tests

- Verify that a complete report with one changed test case and all three result categories passes and renders in the review report.
- Verify that missing task coverage, missing categories, and a case outside changed files fail validation.
- Run the full controller unit suite, Python syntax check, and Git diff check.
