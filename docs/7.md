# Work 7: Link sub-issues in the parent issue body

## What and why

The parent issue must show direct links to every generated sub-issue. GitHub's native sub-issue relationship provides the hierarchy, while links in the parent description keep the ordered work visible alongside the rewritten specification. The original request under `==== original ====` must remain unchanged.

## Detailed sequence and policy

1. Plan and register every sub-issue, recovering existing linked or orphaned generated issues as in work 6.
2. Fetch the current parent issue body after registration. Build an ordered Markdown list with each child number, direct GitHub URL, and one-line task description.
3. Place the list in a managed section bounded by `swfactory-subtask-links` HTML comments. Insert that section immediately above `==== original ====`, or append it if the issue has no original marker.
4. On a retry, replace only the managed section. Skip the issue edit if its body already contains the expected links. Reject a partial managed section rather than risking overwriting owner content.
5. Update the parent before starting task implementation. If this update fails, the normal failure path stops implementation; a later retry reuses the already created children.

## Tests

- Verify direct links, task order, and one-line titles.
- Verify the original request remains intact after insertion.
- Verify replacement on retry does not duplicate the managed section.
- Verify an unchanged section does not trigger another GitHub edit.
- Run the full unit suite and Python syntax check.
